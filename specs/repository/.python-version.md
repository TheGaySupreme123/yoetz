# .python-version — local and CI interpreter selection

**Wave:** F | **ADRs:** ADR-007 | **Imports (spec-tree):** `pyproject.toml.md` | **Imported by:**
`uv`, contributor setup, CI bootstrap, and release build

## Purpose

Select the exact CPython patch used by the active implementation/release lock so local `uv`
commands do not silently use a different interpreter or bundled SQLite identity.

## Public surface

One ASCII line containing the exact advertised CPython patch, initially the ADR-007 candidate
`3.14.6` and refreshed only through the release-lock process.

## Behavior

`uv` and compatible version managers read this file as the default development interpreter.
Runtime support metadata remains the minor range in `pyproject.toml`; write admission still checks
the generated exact platform/runtime support matrix rather than trusting this file.

## Errors and edge cases

A prerelease, implementation alias, range, multiple lines, or value differing from release
evidence fails configuration validation. A tool that ignores the file does not thereby gain write
support.

## Invariants

The file contains no local path and selects one CPython patch. Changing it requires refreshing
lock, capability, platform, and SQLite evidence.

## Tests

`tests/packaging/test_platform_and_sqlite_gate.py` and the clean-install/release workflow.

## Open questions

None.

The exact patch is centralized under E-001 and refreshed at implementation and release lock.
