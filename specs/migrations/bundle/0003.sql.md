# migrations/bundle/0003.sql — encrypted observation authority and verification

**Wave:** D | **ADRs:** ADR-003, ADR-009, ADR-010 | **Imports (spec-tree):**
`specs/src/yoetz/adapters/sqlite/migrations.md`, `specs/src/yoetz/ports/observation.py.md` |
**Imported by:** installed migration mirror and migration/repository tests

## Purpose

Extend schema 2 without rewriting ledger/object/observation rows, owning all unreleased durable
state for encrypted observation content, workspace reopening, exact trust, verification, and advice
history.

## Public surface

Tables: `observation_workspace_bindings`, `observation_content_manifests`,
`observation_logical_identity`, `observation_trusted_check_policies`,
`observation_verification_jobs`, `observation_verification_results`,
`observation_advice_history`, and `observation_advice_delivery`; `PRAGMA user_version=3`.

## Behavior

Workspace/content rows reference encrypted objects. Logical identity binds normalized material to
one operation and merged source mask. Trust rows are exact-policy-digest, encrypted-object, and
state-token bound. Jobs enforce generation leases and one workspace-running selection; results and
advice history are immutable/idempotent identities with currentness/delivery state.

## Errors and edge cases

Foreign-key, state-token, lease-shape, currentness, and uniqueness violations fail atomically.
Upgrade applies only from schema 2; migration failure rolls back the whole transaction.

## Invariants

1. No content, path, transcript, command output, or secret plaintext column exists.
2. Schema 2 rows and all older ledger/object data remain readable.
3. Repositories own every table read/write.

## Tests

Schema-2 upgrade, restart, copied-backup restore, rollback, verification repository, and resource
parity tests.
