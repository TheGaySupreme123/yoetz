# migrations/bundle/0004.sql — inspection snapshots and session routing

**Wave:** D | **ADRs:** ADR-003, ADR-009, ADR-010 | **Imports (spec-tree):**
`specs/src/yoetz/adapters/sqlite/migrations.md`, `specs/migrations/bundle/0003.sql.md` |
**Imported by:** installed migration mirror and migration/repository tests

## Purpose

Extend schema 3 without rewriting migration `0003` or older ledger/object/observation rows.
Owns durable inspection snapshots, workspace→Yoetz-session routing, and session-scoped current
advice used by background verification and `status(view="advice")`.

## Public surface

Tables: `observation_inspection_snapshots`, `observation_workspace_session_routes`,
`observation_session_advice`; `PRAGMA user_version=4`.

## Behavior

Inspection snapshots bind relative-path digests and encrypted fact/excerpt object IDs to a
workspace and Yoetz session; at most one current snapshot per session. Session routes map a
consented workspace commitment to exactly one active Yoetz session/task/writer identity and a
Codex session commitment. Session advice stores the current advice snapshot keyed by
`(workspace_commitment, yoetz_session_id)` so status never returns “latest advice anywhere.”

## Errors and edge cases

Foreign-key, uniqueness, and active/unbound route shape violations fail atomically. Upgrade
applies only from schema 3; migration failure rolls back the whole transaction. Pre-0004
repositories may fall back to workspace-scoped advice reads when session tables are absent.

## Invariants

1. No content, absolute path, transcript, command output, or secret plaintext column exists.
2. Schema 3 rows and all older ledger/object data remain readable; migration `0003` is not edited.
3. Repositories own every table read/write.

## Tests

Schema-3 upgrade, restart, copied-backup restore, rollback, session-scoped advice status, and
resource parity tests.
