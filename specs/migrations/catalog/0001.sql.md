## Purpose

This is the reviewable source for catalog migration `0001`. The future file is SQL, not Python:
it creates the installation-level routing, `start` idempotency, privacy-policy/audit/root state,
maintenance idempotency/fencing, and retained-route recovery database without accepting any task
payload, workspace path, title, prompt, or other user-controlled plaintext. Once v0.1 is
released these bytes are immutable. A correction is a new numbered migration, never an edit to
this file.

## Public surface

The future file exports no programming-language names. Its observable contract is:

- migration family `catalog`, version `0001`, previous version `0000`;
- UTF-8 text with LF endings, one final LF, and no byte-order mark;

## Behavior

### File and statement discipline

The file begins with `PRAGMA application_id = 0x594F4554`. It then creates the nine tables and named
indexes in the order below and ends with `PRAGMA user_version = 1`. Statements are literal SQL; there
are no template substitutions or environment-dependent branches. The runner executes the file on
one connection while holding the exclusive maintenance generation. The file must parse with the
certified SQLite build when `foreign_keys=ON` and `trusted_schema=OFF`.

Every table is `STRICT, WITHOUT ROWID`. All timestamps are canonical UTC strings validated by the
application before binding. The SQL never calls a clock, random function, collation, user-defined
function, or filesystem function.

### `catalog_meta`

Create `catalog_meta(key TEXT PRIMARY KEY, value TEXT NOT NULL) STRICT, WITHOUT ROWID`. It is the
structural installation metadata map. The migration runner seeds only the documented bounded keys:
`installation_id`, `owner_generation`, `owner_nonce`, `heartbeat_at`, and
`storage_schema_version`, plus `privacy_policy_generation` (initial `1`) and
`privacy_audit_store_version` (constant `1`). The schema permits future bounded metadata keys so
adding a key does not require table alteration; the adapter owns the key allowlist.

### `task_routes`

The following literal block is the sole canonical DDL for the routing table and attachment index:

```sql
CREATE TABLE task_routes (
    task_id TEXT PRIMARY KEY,
    workspace_ref_commitment TEXT,
    external_ref_commitment TEXT,
    active_session_id TEXT NOT NULL UNIQUE,
    bundle_relpath TEXT NOT NULL UNIQUE,
    route_generation INTEGER NOT NULL CHECK (route_generation > 0),
    active_route_identity_digest TEXT NOT NULL UNIQUE,
    state TEXT NOT NULL CHECK (state IN ('initializing', 'active', 'quarantined')),
    quarantine_code TEXT,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    CHECK (
        (workspace_ref_commitment IS NULL AND external_ref_commitment IS NULL)
        OR
        (workspace_ref_commitment IS NOT NULL AND external_ref_commitment IS NOT NULL)
    ),
    CHECK (
        (state IN ('initializing', 'active') AND quarantine_code IS NULL)
        OR
        (state = 'quarantined' AND quarantine_code IS NOT NULL)
    )
) STRICT, WITHOUT ROWID;

CREATE UNIQUE INDEX task_routes_scoped_attachment
ON task_routes(workspace_ref_commitment, external_ref_commitment)
WHERE workspace_ref_commitment IS NOT NULL
  AND external_ref_commitment IS NOT NULL;
```

The partial index is the race-safe attachment identity; no raw reference is stored beside it.

### `start_operations`

The following literal block is the sole canonical DDL for installation-scoped start idempotency
and recovery:

```sql
CREATE TABLE start_operations (
    installation_id TEXT NOT NULL,
    operation_id TEXT NOT NULL,
    request_digest TEXT NOT NULL,
    requested_mode TEXT NOT NULL
        CHECK (requested_mode IN ('create', 'attach', 'create_or_attach')),
    route_action TEXT NOT NULL CHECK (route_action IN ('created', 'attached')),
    state TEXT NOT NULL CHECK (state IN ('pending', 'complete', 'quarantined')),
    phase TEXT NOT NULL CHECK (phase IN (
        'route_reserved',
        'bundle_ready',
        'lifecycle_committed',
        'result_published',
        'terminal'
    )),
    task_id TEXT NOT NULL REFERENCES task_routes(task_id),
    session_id TEXT NOT NULL,
    writer_id TEXT NOT NULL,
    lifecycle_event_id TEXT NOT NULL,
    route_generation INTEGER NOT NULL CHECK (route_generation > 0),
    route_identity_digest TEXT NOT NULL,
    owner_generation TEXT,
    lease_owner_id TEXT,
    lease_generation INTEGER CHECK (lease_generation > 0),
    lease_expires_at TEXT,
    response_object_id TEXT,
    terminal_result_canonical BLOB,
    terminal_result_digest TEXT,
    quarantine_code TEXT,
    terminal_at TEXT,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    PRIMARY KEY (installation_id, operation_id),
    CHECK (
        (
            state = 'pending'
            AND phase != 'terminal'
            AND owner_generation IS NOT NULL
            AND lease_owner_id IS NOT NULL
            AND lease_generation IS NOT NULL
            AND lease_expires_at IS NOT NULL
            AND terminal_result_canonical IS NULL
            AND terminal_result_digest IS NULL
            AND quarantine_code IS NULL
            AND terminal_at IS NULL
            AND (phase != 'result_published' OR response_object_id IS NOT NULL)
        )
        OR
        (
            state = 'complete'
            AND phase = 'terminal'
            AND owner_generation IS NULL
            AND lease_owner_id IS NULL
            AND lease_generation IS NULL
            AND lease_expires_at IS NULL
            AND response_object_id IS NOT NULL
            AND terminal_result_canonical IS NOT NULL
            AND terminal_result_digest IS NOT NULL
            AND quarantine_code IS NULL
            AND terminal_at IS NOT NULL
        )
        OR
        (
            state = 'quarantined'
            AND phase = 'terminal'
            AND owner_generation IS NULL
            AND lease_owner_id IS NULL
            AND lease_generation IS NULL
            AND lease_expires_at IS NULL
            AND terminal_result_canonical IS NOT NULL
            AND terminal_result_digest IS NOT NULL
            AND quarantine_code IS NOT NULL
            AND terminal_at IS NOT NULL
        )
    )
) STRICT, WITHOUT ROWID;
```

The SQL intentionally cannot express monotonic phase movement or canonical-result/digest equality;
the start-catalog adapter checks those in the same transaction as each transition. The operation's
route pair is copied from the selected `task_routes` row at reservation and never updated; final
completion requires the current route still has that generation/digest, so a restore switch fences
the stale start allocation.

### Privacy policy and transition state

Privacy policy is an installation authority and therefore lives in the catalog, not in a task
ledger. Both tables below are `STRICT, WITHOUT ROWID`. Their canonical BLOB fields contain only
the closed structural schemas described here; adapters validate canonical bytes and matching
digests before insert/read. They never contain excerpts, request/response bytes, credentials, URLs,
paths, prompts, exception text, or raw provider output.

Create current/history policy storage exactly as follows:

```sql
CREATE TABLE privacy_policy_versions (
    policy_id TEXT NOT NULL,
    policy_version INTEGER NOT NULL CHECK (policy_version > 0),
    scope_digest TEXT NOT NULL,
    scope_kind TEXT NOT NULL
        CHECK (scope_kind IN ('machine', 'workspace', 'task', 'request')),
    installation_id TEXT NOT NULL,
    workspace_ref_commitment TEXT,
    task_id TEXT REFERENCES task_routes(task_id),
    request_id TEXT,
    policy_digest TEXT NOT NULL,
    policy_canonical BLOB NOT NULL,
    policy_generation INTEGER NOT NULL UNIQUE CHECK (policy_generation > 0),
    change_kind TEXT NOT NULL
        CHECK (change_kind IN ('seed', 'tightening', 'human_expansion')),
    source_proposal_id TEXT,
    state TEXT NOT NULL CHECK (state IN ('current', 'superseded')),
    created_at TEXT NOT NULL,
    superseded_at TEXT,
    PRIMARY KEY (policy_id, policy_version),
    UNIQUE (scope_digest, policy_version),
    CHECK (
        (scope_kind = 'machine'
            AND workspace_ref_commitment IS NULL AND task_id IS NULL AND request_id IS NULL)
        OR (scope_kind = 'workspace'
            AND workspace_ref_commitment IS NOT NULL AND task_id IS NULL AND request_id IS NULL)
        OR (scope_kind = 'task'
            AND workspace_ref_commitment IS NOT NULL AND task_id IS NOT NULL AND request_id IS NULL)
        OR (scope_kind = 'request'
            AND workspace_ref_commitment IS NOT NULL AND task_id IS NOT NULL AND request_id IS NOT NULL)
    ),
    CHECK (
        (change_kind = 'human_expansion' AND source_proposal_id IS NOT NULL)
        OR (change_kind IN ('seed', 'tightening') AND source_proposal_id IS NULL)
    ),
    CHECK (
        (state = 'current' AND superseded_at IS NULL)
        OR (state = 'superseded' AND superseded_at IS NOT NULL)
    )
) STRICT, WITHOUT ROWID;

CREATE UNIQUE INDEX privacy_policy_versions_one_current_scope
ON privacy_policy_versions(scope_digest)
WHERE state = 'current';
```

`policy_canonical` is the exact closed `PrivacyPolicy`/overlay structural value. The globally
monotonic generation equals catalog meta `privacy_policy_generation` for the committed row. A
change inserts a new current row and supersedes the prior row in one transaction; tightening uses
`change_kind=tightening`, while widening must name its committed proposal. Historical policy bytes
are immutable.

Prepared widening decisions use this exact structural table:

```sql
CREATE TABLE privacy_policy_transitions (
    proposal_id TEXT PRIMARY KEY,
    scope_digest TEXT NOT NULL,
    base_policy_id TEXT NOT NULL,
    base_policy_version INTEGER NOT NULL CHECK (base_policy_version > 0),
    base_policy_generation INTEGER NOT NULL CHECK (base_policy_generation > 0),
    proposal_digest TEXT NOT NULL UNIQUE,
    candidate_policy_digest TEXT NOT NULL,
    candidate_policy_canonical BLOB NOT NULL,
    diff_canonical BLOB NOT NULL,
    state TEXT NOT NULL CHECK (state IN ('pending', 'committed', 'denied', 'expired', 'stale')),
    human_decision TEXT CHECK (human_decision IN ('approved', 'denied')),
    decision_digest TEXT,
    authority_commitment TEXT,
    committed_policy_id TEXT,
    committed_policy_version INTEGER CHECK (committed_policy_version > 0),
    expires_at TEXT NOT NULL,
    terminal_at TEXT,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL,
    FOREIGN KEY (base_policy_id, base_policy_version)
        REFERENCES privacy_policy_versions(policy_id, policy_version),
    FOREIGN KEY (committed_policy_id, committed_policy_version)
        REFERENCES privacy_policy_versions(policy_id, policy_version),
    CHECK (
        (state = 'pending'
            AND human_decision IS NULL AND decision_digest IS NULL
            AND authority_commitment IS NULL AND committed_policy_id IS NULL
            AND committed_policy_version IS NULL AND terminal_at IS NULL)
        OR (state = 'committed'
            AND human_decision = 'approved' AND decision_digest IS NOT NULL
            AND authority_commitment IS NOT NULL AND committed_policy_id IS NOT NULL
            AND committed_policy_version IS NOT NULL AND terminal_at IS NOT NULL)
        OR (state = 'denied'
            AND human_decision = 'denied' AND decision_digest IS NOT NULL
            AND authority_commitment IS NULL AND committed_policy_id IS NULL
            AND committed_policy_version IS NULL AND terminal_at IS NOT NULL)
        OR (state IN ('expired', 'stale')
            AND human_decision IS NULL AND decision_digest IS NULL
            AND authority_commitment IS NULL AND committed_policy_id IS NULL
            AND committed_policy_version IS NULL AND terminal_at IS NOT NULL)
    )
) STRICT, WITHOUT ROWID;

CREATE INDEX privacy_policy_transitions_scope_state
ON privacy_policy_transitions(scope_digest, state, expires_at);
```

`candidate_policy_canonical` and `diff_canonical` contain only IDs, enum/category names, digests,
ceilings, scope commitments, and expiry. A content-bearing policy proposal is invalid in v0.1.
Commit performs a generation/digest CAS, inserts the new policy version, supersedes the old one,
increments catalog meta generation, and closes this row atomically.

`subject_lookup_identity` is the pre-dispatch structural digest, agent projection's installation-
keyed projection commitment, or disclosure proposal's installation-keyed proposal commitment. The
catalog never stores an unkeyed digest derived from projection/prepared plaintext.
`subject_structural_canonical`, decision/authorization/attempt structural records, and their keyed
commitments omit excerpts, result values, raw model output, and unkeyed content digests. The
encrypted `DisclosureProposal` is reachable only through its exact ObjectRef columns.

`AgentProjectionAuditSubject` is deliberately objectless even when approved bytes are returned:
the authoritative result remains in existing task objects, while the audit row carries only keyed
internal-result/projection commitments, sorted pointer/category allow-or-omit decisions, counts,
scope/policy/method identity, and receipt. Its reserve, baseline approval, local consume, and local
completion commit atomically before ordinary client serialization. `privacy_proposal_id` is the
local replay/attempt key, so the catalog invents neither a local dispatch ID nor an external
authorization.

The adapter validates the full state transition graph in the same `BEGIN IMMEDIATE` transaction as
each row update. `consume` is the only `authorized -> receipt_pending` CAS; `consume_local` is the
only `approved -> local_disclosure_pending` CAS. Human denial remains `denied`, authorization
expiry/staleness/reuse remains `expired`, and all other terminal pre-consume decisions complete as
`decision_completed`; each terminal state carries its durable compatible receipt. Receipt lookup
and listing use only denormalized structural columns/canonical receipt and never dereference the
content object. Cursor authentication remains service-owned, not a SQL field.

Catalog-owned encrypted-object reachability uses this exact table:

```sql
CREATE TABLE privacy_root_sets (
    task_id TEXT PRIMARY KEY REFERENCES task_routes(task_id),
    route_identity_digest TEXT NOT NULL,
    root_generation INTEGER NOT NULL CHECK (root_generation >= 0),
    root_count INTEGER NOT NULL CHECK (root_count >= 0),
    root_digest TEXT NOT NULL,
    updated_at TEXT NOT NULL
) STRICT, WITHOUT ROWID;
```

The first root-bearing reservation creates generation `1`; a rootless task is represented by an
absent row and the canonical generation-0 empty-root digest. Inserting a content reference and
updating `privacy_root_sets` are one transaction: recompute the ASCII-object-ID-sorted root digest,
increment generation exactly once, and bind the current active route identity. v0.1 has no clear
operation, so terminal age/state never decrements count or changes the root set. Agent projection
rows never enter this set because they own no duplicate object. A route switch verifies all refs in
the target and updates only `route_identity_digest` in the same maintenance CAS; root generation/
digest remain unchanged. Any stored count/digest mismatch or missing/wrong object quarantines the
affected audit row and prevents backup/restore/content disclosure; it never clears the ref or
invents task-ledger inventory.

### `maintenance_operations`

Maintenance idempotency lives in the installation catalog, not a task bundle, because a verified
restore may switch which bundle route is active. Create this exact strict, without-rowid table:

```sql
CREATE TABLE maintenance_operations (
    installation_id TEXT NOT NULL,
    operation_id TEXT NOT NULL,

    requested_target_version TEXT,

    backup_manifest_digest TEXT,

    result_digest TEXT,

    updated_at TEXT NOT NULL,

    CHECK (
        (kind = 'backup' AND phase IN (
            'reserved', 'pinned', 'database_ready', 'objects_ready',
            'manifest_ready', 'terminal'
        ))
        OR
        (kind = 'restore' AND phase IN (
            'reserved', 'source_verified', 'target_ready', 'target_verified',

        (kind = 'backup'

        state != 'pending'

        (kind = 'backup'

            ))
        OR

                phase = 'reserved'

ON maintenance_operations(task_id)
WHERE state = 'pending';

CREATE INDEX maintenance_operations_task_state
ON maintenance_operations(task_id, state, kind);
```

All fields are structural. `source_location_commitment` and `target_location_commitment` are keyed,
domain-separated commitments computed before the transaction; the source/destination path is never
stored. `source_route_identity_digest` binds the plan to the active catalog route.
`privacy_root_generation`/`privacy_root_digest` bind the plan to the complete current catalog audit-
object root set; a rootless task uses generation `0` and the canonical empty-root digest.
`target_route_identity_digest` is null until a restore allocates its generated target and may be set
only during a fenced phase CAS. `result_canonical` contains IDs, versions, frontiers, digests,
counts and bounded reasons only.

Phase changes use `UPDATE ... WHERE installation_id=? AND operation_id=? AND state='pending' AND
phase=? AND owner_generation=? AND lease_owner_id=? AND lease_generation=?`; exactly one changed row
is required. A lease is live only when owner generation equals current `catalog_meta` generation and
expiry is future. Expiry alone grants nothing: reclaim advances generation/lease through one CAS.
The unique pending index prevents two maintenance operations from holding authority over one task.

### `retained_task_routes`

Restore never overwrites or discards the prior active route. Create this recovery record after the
maintenance table:

```sql
CREATE TABLE retained_task_routes (
    installation_id TEXT NOT NULL,
    task_id TEXT NOT NULL REFERENCES task_routes(task_id),
    route_generation INTEGER NOT NULL CHECK (route_generation > 0),
    bundle_relpath TEXT NOT NULL UNIQUE,
    route_identity_digest TEXT NOT NULL UNIQUE,
    retained_by_operation_id TEXT NOT NULL,
    retained_reason TEXT NOT NULL
        CHECK (retained_reason IN ('restore_replaced', 'migration_rollback', 'quarantine')),
    state TEXT NOT NULL CHECK (state IN ('retained', 'quarantined', 'released')),
    quarantine_code TEXT,
    frontier_seq INTEGER NOT NULL CHECK (frontier_seq >= 0),
    frontier_digest TEXT NOT NULL,
    retained_at TEXT NOT NULL,
    released_at TEXT,
    PRIMARY KEY (installation_id, task_id, route_generation),
    FOREIGN KEY (installation_id, retained_by_operation_id)
        REFERENCES maintenance_operations(installation_id, operation_id),
    CHECK (
        (state = 'retained' AND quarantine_code IS NULL AND released_at IS NULL)
        OR
        (state = 'quarantined' AND quarantine_code IS NOT NULL AND released_at IS NULL)
        OR
        (state = 'released' AND released_at IS NOT NULL)
    )
) STRICT, WITHOUT ROWID;

CREATE INDEX retained_task_routes_task_state
ON retained_task_routes(task_id, state, route_generation);
```

`bundle_relpath` is a Yoetz-generated contained route, never a user path. Retention does not mean
writable: only `task_routes` names the active route. Release is a separately authorized retention
operation and never deletes files inside the catalog transaction.

The restore switch is one `BEGIN IMMEDIATE` CAS: verify the current catalog owner generation and
that the new generated route/path appears in neither active nor retained routes;
select `task_routes` by task ID, old `route_generation`, old `bundle_relpath`, old
`active_route_identity_digest`, active state and expected session; match the maintenance operation's
privacy-root generation/digest and verify every current catalog root in the target; insert the old
row into `retained_task_routes`; update the active row to the verified generated `bundle_relpath`,
`route_generation + 1`, and new route identity digest; advance the maintenance phase
`target_verified → route_switched`; update any `privacy_root_sets` row to the new route identity
without changing its generation/digest; then COMMIT. Any zero-row/constraint failure rolls back the
entire switch. A retry after COMMIT observes the terminal/route identity and never switches twice.

### Transaction outcome

The runner treats the complete file as one migration unit. After execution it verifies application
ID, user version, table/index inventory, `STRICT`/`WITHOUT ROWID` flags, foreign-key metadata, and
the normalized schema digest before seeding metadata. Any mismatch aborts initialization; the
staging database is never routed as active.

## Errors and edge cases

- Existing objects cause migration failure; `0001` is valid only from an uninitialized database.
- A SQLite build that rejects any required feature is unsupported and yields the adapter's bounded
  storage-identity failure, never a fallback schema.
- Duplicate scoped commitments fail the unique index. The application re-resolves the route;
  migration SQL does not use `INSERT OR REPLACE`.
- Unknown state/mode/phase/kind/retention strings and zero/negative lease or route generations fail
  constraints.
- Maintenance phase movement without matching owner/lease generation, a second pending operation for
  one task, or a route switch with stale route identity affects zero rows and fails closed.
- `PRAGMA` or DDL failure rolls back where SQLite permits; the runner verifies no partially routed
  catalog is accepted even if platform behavior differs.
- SQL error strings, bound values, and absolute database paths never enter public errors or release
  evidence.

## Invariants

1. Catalog rows contain structural IDs, commitments, states, bounded codes, and canonical terminal
   bytes only; never user content.
2. One installation/operation key can name only one durable start or maintenance allocation within
   its owning table.
3. One non-null commitment pair can route to only one task.
4. Pending rows hold a complete current-generation lease; terminal rows hold none.
5. A route switch retains the previous generated route, preserves the exact privacy-root set, and
   advances its positive route generation exactly once in the same catalog transaction.
6. No catalog maintenance/retention column stores a source/destination path or user payload.
7. Schema version and released SQL bytes are append-only after publication.
8. The embedded wheel copy is byte-identical to this reviewable source.
9. Policy/audit canonical fields are structural-only; content-bearing disclosure proposals live in
   encrypted task objects, and agent projections store keyed commitments without duplicate content.
10. Every catalog privacy object ref remains in the monotonic live-root set independently of task-
    ledger inventory until an owning clear transaction exists; v0.1 has none.
