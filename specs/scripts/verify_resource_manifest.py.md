# scripts/verify_resource_manifest.py — synchronize and prove packaged resource parity

**Wave:** A/F | **ADRs:** ADR-003, ADR-006, ADR-007 | **Imports (spec-tree):**
`specs/src/yoetz_core/resources/manifest.json.md`, root resource specs | **Imported by:** PR CI,
packaging tests, release construction

## Purpose

Maintain the exact relationship between reviewable public resource sources and the bytes installed
inside the wheel. The script is the sole repository tool allowed to copy canonical resources into
`src/yoetz_core/resources/` and regenerate its manifest. Its default verification mode is strictly
read-only.

## Public surface

- `load_inventory_config() -> ResourceInventory` — checked-in, code-owned source/destination map;
- `collect_source_entries(inventory) -> tuple[CollectedResource, ...]`;
- `build_manifest(entries) -> bytes`;
- `verify_resource_tree(entries, manifest_bytes) -> ResourceDiff`;
- `sync_resource_tree(entries, manifest_bytes) -> None`;
- `main(argv=None) -> int`.

Commands:

```text
uv run --locked python scripts/verify_resource_manifest.py --check
uv run --locked python scripts/verify_resource_manifest.py --sync
```

One mode is mandatory. Test-only `--repo-root` may target a temporary synthetic repository. Exit
codes are `0` exact, `1` drift/integrity/policy failure, `2` bad invocation.

## Behavior

### Inventory ownership

The inventory is an explicit ordered constant or small public config committed beside the script;
it is not generated by scanning every repository file. Each entry declares logical name, source,
package destination, kind, media type, size cap, text/binary policy, and optional contract version.
The script validates those values using the resource-manifest contract before opening files.

Permitted source roots are the public `schemas/`, `migrations/`, `skills/`, named canonical-vector
fixtures, and named policy/template roots. It never reads ignored/local planning documents,
transcripts, user configuration, `.git`, build caches, virtual environments, temp outputs, or a
home-relative fallback. Sources and destinations must be regular non-symlink files inside their
declared roots.

### Collection and validation

For each explicit entry, use descriptor-based/stat-before-and-after reads to reject file changes
during collection. Enforce kind byte cap, compute raw SHA-256 and size, and apply kind-specific
format checks. Text resources must be UTF-8 without BOM, LF-only, and final-LF. JSON must be
canonical and reject duplicate keys/floats. SQL must satisfy the migration spec's statement
discipline. Skill Markdown must pass public-boundary and link/path checks.

After explicit collection, enumerate package-resource files and canonical source subtrees to detect
unmapped additions. A file is never silently included merely because it appears in an allowlisted
directory; the inventory must be deliberately extended in review.

### Manifest generation

Build entries sorted by ASCII logical name with exact source/package paths, kind, media type, size,
SHA-256, and optional version. Compute the resource-set digest exactly as specified by
`resources/manifest.json.md`; render canonical JSON with LF and final newline. No time, Git, host,
user, absolute path, environment, secret, or machine identity enters output.

The manifest does not list itself as a normal entry. Verification separately checks its canonical
encoding and set digest.

### `--check`

Read the existing package manifest and embedded files and require:

- generated manifest bytes equal checked-in manifest bytes;
- every source equals its package destination byte-for-byte;
- no missing, extra, symlinked, duplicate, traversing, or case-colliding file;
- destination inventory is exactly the manifest inventory;
- generated and installed-loader parsers agree on schema and set digest.

Output one bounded line per mismatch with logical name, category, and digest prefixes. Never print
resource contents or absolute checkout paths. This mode opens no file for writing.

### `--sync`

First run every collection/format/boundary check. Stage a complete generated package-resource tree
and manifest beneath the repository's build-temp root, fsync files/directories, and verify the
staged tree. Then replace only inventory-owned destination files atomically. If an unknown existing
destination would be removed or overwritten, abort without changing it. Rerun `--check`; success
means a clean deterministic result.

The script never edits canonical sources. It does not run schema generation or migration creation,
and it does not commit/stage Git changes. Maintainers review source, copied bytes, and manifest diff.

### Build/install verification

Packaging and release jobs run `--check` before build, inspect wheel/sdist inventories, install the
artifact, and call the runtime verifier against installed package resources. Matching source-tree
files alone is insufficient evidence that the artifact contains them.

## Errors and edge cases

- Read race, symlink, non-regular file, path escape/collision, size cap, invalid format, secret/
  private-boundary hit, or unlisted file fails closed.
- Interrupted sync leaves either prior checked-in bytes or staged temp output; it never claims
  success until post-replacement check passes.
- Windows newline checkout conversion is unsupported for canonical resources and produces drift.
- Missing canonical source is not repaired from the package copy.
- Runtime package-resource APIs may materialize temporary paths; verification compares bytes, not
  inode/path identity.
- Diagnostics are bounded structural fields and are themselves scanned before CI artifact upload.

## Invariants

1. Canonical public sources are the only authority for installed resource bytes.
2. `--check` performs zero writes.
3. `--sync` cannot absorb an unreviewed file through directory discovery.
4. Manifest output is deterministic across supported platforms.
5. Clean source parity and clean installed-artifact parity are separate required gates.
