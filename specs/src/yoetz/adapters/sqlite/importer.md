## Purpose

`SqliteImporter` is the production task-scoped implementation of `ImporterPort`. It durably owns
source-level idempotency aliases, the one-job-per-source state machine, stable batch/report
identities, generation-fenced leases, crash recovery, bounded status, and frozen review manifests
inside the same task bundle as the ledger.

It does not parse by guess, append events directly, or inspect a repository. It delegates exact
source parsing/mapping to the pure Codex adapter, exact object publication/authentication to
`ObjectStorePort`, and all observation/report event commits to application `publish_work` through
`LedgerPort`. SQLite contains only structural IDs, keyed commitments, safe digests/counts/ranges,
canonical result envelopes, phases, and object inventory—not source/payload/argv/cwd/stderr text or
ordinary source/stderr audit digests.

## Public surface

- `class SqliteImporter(ImporterPort)` implementing all registered methods:
  `capture`, `reserve_or_resume`, `prepare_plan`, `publish_plan`, `next_batch`, `record_batch`,
  `prepare_report`, `publish_report`, `status`, `complete`, `quarantine`, and
  `load_review_source`.
- `@dataclass(frozen=True, slots=True) class SqliteImportPolicy` with the release-frozen v0.1
  values shared with `MemoryImportPolicy`:
  - source cap 4 MiB;
  - stderr prefix/commitment input 64 KiB;
  - physical line cap 1 MiB and aggregate line cap 20,000;
  - batch cap 1,024 in addition to the public 100-event/1-MiB request caps;
  - 60-second job lease, 30-second minimum renewed publication window;
  - status page cap 64.
- `IMPORT_SCHEMA_VERSION = 1` — schema component version recorded in `bundle_meta` and the
  migration/resource manifest; it does not replace bundle `PRAGMA user_version`.

Constructor contract:

`SqliteImporter(*, task_id, admitted_session_id, ownership_fence, writer: SqliteWriterThread,
read_factory, objects: ObjectStorePort, ledger: LedgerPort, clock: ClockPort, ids: IdPort,
policy: SqliteImportPolicy)`.

The importer shares the exact task's one `SqliteWriterThread` and `OwnershipFence` with
`SqliteLedgerRepository`. It never opens a second writer connection. Read-only `status`/review row
snapshots use bounded query-only connections; every mutation is a submitted writer job.

## Behavior

### Physical schema and migration ownership

Bundle migration `0001` creates these importer tables before the runtime can advertise import
capability. The DDL is owned/generated by `adapters/sqlite/migrations.py`; this file reproduces the
behavioral columns and constraints it must match.

`import_request_aliases`:

| Column | Contract |
|---|---|
| `requesting_writer_id`, `request_id` | composite primary key; validated IDs; writer belongs to this task/session |
| `request_digest` | canonical logical request digest |
| `source_identity_digest` | FK to exactly one `import_jobs` row |
| `created_at` | canonical metadata timestamp |

`import_jobs`:

| Column group | Contract |
|---|---|
| identity | primary-key `source_identity_digest`; `task_id`, `session_id`, `source_commitment`, `codex_capability_profile_id`, `mapping_version`, immutable `publishing_writer_id` |
| capture | `source_object_id`, `capture_metadata_object_id` FKs to object inventory, source/object commitments, byte/line counts, final-newline flag, safe `metadata_digest` |
| state | `state pending|complete|quarantined`; `phase source_reserved|plan_ready|publishing|report_ready|report_published|terminal`; monotonic `job_revision` |
| lease | nullable `owner_generation`, `lease_owner_id`, positive `lease_generation`, canonical `lease_expires_at` |
| plan | nullable `plan_digest`; `batch_count`, `completed_batch_count`; preallocated `report_request_id`, `report_event_id`, `report_evidence_id` |
| report-ready | nullable `report_object_id`, `report_digest`, safe `report_result_canonical`/digest, `report_evidence_draft_canonical`/digest |
| report-published | nullable `report_append_result_canonical`/digest and report event ingestion sequence/entry digest |
| terminal | nullable `terminal_result_canonical`/digest, `quarantine_code`, `terminal_at`; plus `created_at`, `updated_at` |

`import_batches`:

| Column | Contract |
|---|---|
| `source_identity_digest`, `batch_index` | composite primary key; index is zero-based, `< job.batch_count` |
| `state` | `planned|complete` |
| `request_id` | stable batch publication request ID |
| `plan_object_id` | FK to object inventory; exact finalized `import_plan` object |
| `plan_object_commitment`, `plan_digest` | exact object/logical plan identity |
| `event_ids_canonical`, `event_ids_digest`, `event_count` | safe ordered stable IDs, bounded and canonical |
| completion fields | nullable `append_result_canonical`/digest, subject/result frontiers, first/last ingestion sequence, `completed_at` |
| timestamps | `created_at`, `updated_at` |

Indexes are:

- unique source identity primary key;
- aliases by `source_identity_digest`;
- `import_jobs(session_id, state, source_identity_digest)` for the atomic pending gate/status;
- `import_jobs(session_id, terminal_at, source_identity_digest)` for bounded terminal status;
- `import_batches(source_identity_digest, state, batch_index)` for next-batch selection;
- unique `(publishing_writer_id, request_id)` across planned batches/report publication identities
  through migration triggers/auxiliary indexes, preventing reuse under one writer.

CHECK constraints enforce:

- `source_reserved`: no plan/report fields, batch counts zero;
- `plan_ready|publishing`: complete plan/report IDs, `0 <= completed <= batch_count`, no report;
- `report_ready`: every batch complete and exact report/evidence draft present, no report append;
- `report_published`: report-ready fields plus exact report append/evidence locator;
- `pending`: nonterminal phase and all four lease fields present, no terminal fields;
- `complete`: `terminal`, no lease/quarantine, exact terminal/report/evidence fields present;
- `quarantined`: `terminal`, no lease, allowlisted quarantine and stable terminal fields present;
- complete batch: all completion fields present and ordered IDs exactly match the planned row;
  planned batch: all completion fields null.

All finalized capture/plan/report refs are inserted-or-verified into the existing `objects`
inventory in the same transaction that first references them. Exact existing row is replay;
different kind/size/commitment/ciphertext/key-slot identity is `STORAGE_CORRUPT`. A duplicate
capture not selected by source identity is never inserted and remains an object-store orphan.
Object GC treats nonterminal/terminal importer refs as roots under its retention policy.

`bundle_meta.import_schema_version` must equal `IMPORT_SCHEMA_VERSION`; missing/older is
`MIGRATION_REQUIRED`, newer is `STORAGE_UNSAFE`, and disagreement with the manifest is
`STORAGE_CORRUPT`.

### Transaction and generation discipline

Every submitted writer job begins `BEGIN IMMEDIATE`, captures one already-supplied canonical
`now`, then rechecks:

- task/session and bundle meta identity;
- current `owner_generation` and owner nonce equal `OwnershipFence`;
- source/job/publishing-writer identity;
- current state/phase and exact expected `job_revision`/lease owner/generation/expiry;
- any object/plan/batch/report values used by the transition.

It commits one transition or rolls back. No object open/finalize, parser, ledger call, clock read,
ID allocation, log, or network call happens inside the transaction. Busy past the shared 5-second
timeout is `BUNDLE_BUSY`; there is no unbounded retry. Lease validity is current generation **and**
strictly future expiry. A stale generation is invalid immediately; reclaim increments lease
generation and never revives an old holder.

The adapter reconstructs return values from the committed row after COMMIT. Cancellation while a
writer job runs does not cancel SQLite work; identical retry observes the durable row.

### Capture exact bytes before allocation

`capture` performs no SQLite transaction:

1. exact-profile/metadata validation;
2. one-shot source read with declared-size check and cap-plus-one 4-MiB enforcement, exact byte/
   line/final-newline accounting, and unconditional close;
3. ordinary SHA-256 computed only for encrypted audit metadata; stage/finalize one exact
   `import_source`, whose keyed commitment is structural;
4. pure Codex argv sanitization and bundle-keyed cwd audit commitment;
5. optional stderr prefix read capped at 64 KiB plus one: record present/count/truncated and
   `objects.commitment_for(prefix, import_stderr)`, compute ordinary digest for encrypted audit,
   close and discard bytes; never stage stderr and never drain an unbounded remainder;
6. stage/finalize one `import_source_manifest` containing audit digests/sanitized metadata and
   exact source ref; return `CapturedImportSource` only after both objects authenticate.

Failure/cancellation may leave temp/finalized orphans but no DB state. Source/stderr/argv/cwd
plaintext and ordinary audit digests never enter the object inventory row, SQL parameters for
import tables, structural result, log, or exception.

### Source-level reservation and alias replay

`reserve_or_resume` recomputes the claimed source identity from the captured source before
submitting one transaction:

1. Existing alias + different request/source digest is `IDEMPOTENCY_CONFLICT`; identical follows
   its job.
2. Existing terminal job inserts/verifies a new alias if needed and returns `replayed` with the
   original terminal report/quarantine envelope; new capture objects remain orphans.
3. Existing pending job from a different requesting writer returns `OPERATION_PENDING`; only the
   frozen publishing writer may resume it.
4. Same publisher + live lease returns `OPERATION_PENDING`; expired/stale generation is reclaimed
   by CAS, `lease_generation + 1`, and returns `resumed` at recorded phase.
5. No job: insert source and metadata object inventory rows, insert one
   `pending/source_reserved` job with publishing writer and lease generation 1, insert alias, and
   commit atomically.

A unique-source race is resolved inside SQLite: the losing transaction re-selects the winner and
applies the same replay/pending rules, never a second event set. Alternate safe capture metadata
produces `source_already_imported_metadata_differs`; first accepted capture remains authoritative.

### Prepare and durably publish the plan

`prepare_plan` snapshots/verifies the leased `source_reserved` job on the writer thread, then
outside SQLite authenticates the source/metadata objects, parses/maps through the exact Codex
profile, allocates all UUIDv4-backed candidate/batch/report IDs, deterministically partitions
under 100-event/1-MiB request and 1,024-batch caps, and finalizes one `import_plan` object per
batch. It returns `PreparedImportPlan` without DB mutation. Before plan commit, retry may create
different orphan objects/IDs.

`publish_plan` pre-verifies all refs/canonical manifests outside SQLite, then one transaction:

- rechecks lease/revision/source_reserved;
- inserts-or-verifies every plan object inventory row;
- inserts all ordered batch rows and their exact request/event ID sets;
- stores plan digest/counts and preallocated report IDs;
- advances to `plan_ready` and increments revision.

The batch inserts and phase advance are all-or-nothing. Existing byte-identical plan is replay;
different plan at/after `plan_ready` is a durable contradiction, never overwrite.

### Select, publish externally, and record a batch

`next_batch` runs one short transaction for `plan_ready|publishing`: select the smallest planned
batch, validate lease, extend expiry to at least the 30-second publication window, increment job
revision, commit, and return refreshed allocation plus a structural row snapshot. No remaining row
returns `batch=None` with that same refreshed allocation.

After COMMIT, open/authenticate the selected plan object and reconstruct the exact `ImportBatch`;
remeasure request/event caps and compare every ID/digest. Corruption fails before application
publication. Global ledger writes may interleave, but this job always selects its own lowest batch.

Application publishes through `publish_work`. `record_batch` validates the resulting canonical
`AppendResult` outside SQLite, then one transaction:

- verifies exact ordered event IDs/row/job/lease;
- identical complete result returns idempotently;
- different accepted identity/result is corruption;
- planned row stores result/digest/frontiers/sequences and becomes complete;
- increments completed count, advances first completion to `publishing`, increments revision.

A crash after event append but before this commit leaves the row planned. Stable request/event IDs
make `publish_work` replay, and the repeated record transaction heals it.

### Pin report and evidence before publishing

After no batch remains, application builds/finalizes the deterministic `import_report`.
`prepare_report` authenticates/decodes it and recomputes source/plan/batch counts/digests/frontiers
outside SQLite. It creates the exact safe `evidence_recorded(import_report)` draft using
preallocated IDs. One transaction then requires every batch complete, inserts/verifies the report
object inventory row, stores exact report ref/digest/safe terminal result and canonical evidence
draft/digest, renews lease, advances to `report_ready`, and increments revision.

At `report_ready`, only the stored object/draft may be used. A different ref/draft is corruption.
After ordinary publication, `publish_report` verifies the `AppendResult` accepted/replayed exactly
the pinned report event and object/digest, then one transaction stores canonical result/digest/
evidence locator and advances to `report_published`.

`complete` authenticates the pinned report outside SQLite, then one transaction rechecks all
batch/report/evidence identities, writes stable terminal result/digest, clears lease fields, and
sets `complete/terminal`. Acknowledgement follows COMMIT. A response lost at any boundary is
resolved from phase and stable IDs; no report object or event is rebuilt after `report_ready`.

`quarantine` is a leased one-transaction terminal transition for verified contradiction only. It
stores an allowlisted `ImportSafeReason`, safe terminal envelope/digest, clears leases, and retains
all structural evidence/object roots. Malformed/unknown lines, unsupported categories, partial
progress, storage busy/full, key lock, or cancellation do not quarantine.

### Status and atomic check/receipt gate

`status(session_id)` uses one bounded query-only read transaction:

- aggregate pending/complete/quarantined counts;
- select at most 64 pending jobs ordered by identity digest with phase and completed/total counts;
- select bounded newest terminal report locators ordered by terminal sequence then identity;
- compute truncation/next-page safe fields when more rows exist.

It returns `ImportStatusSnapshot` and no object/capture plaintext.

Correctness does not rely on a prior status read. Because `import_jobs` shares the task database,
`SqliteLedgerRepository.freeze_case`, `commit_check_if_current`, and receipt `append_batch`
execute `NOT EXISTS (SELECT 1 FROM import_jobs WHERE session_id=? AND state='pending')` inside
their own authoritative transaction immediately before freezing/finalizing/appending. If false,
they return retryable `OPERATION_PENDING`. The index above makes this bounded. An import that
finishes between check phases still changes the ledger frontier through final report evidence, so
the check dependency/final-currentness guard detects staleness.

### Read-only review snapshot

`load_review_source(identity, through)` performs a short read transaction that selects the exact
job and ordered rows only—never filename/cwd/text matching. Missing returns `None`; quarantined or
structurally contradictory state is `STORAGE_CORRUPT`. It snapshots one `job_revision`, releases
the transaction, then authenticates all required source/plan/report objects and verifies accepted
batch/report event IDs/frontiers through ordinary ledger reads.

Every selected event must be wholly at/before `through`; a frontier cutting a batch/report is
`INVALID_REQUEST`. Complete jobs require all batches plus report evidence. Pending jobs include
only complete batches, retain planned gaps from authenticated plans, and set `import_incomplete`;
planned events never appear observed. A final bounded read verifies the job revision is unchanged
or has only monotonically advanced without contradicting the snapshotted completed rows. It
acquires no lease and writes nothing.

## Errors and edge cases

- Public error set matches `ports/importer.md`: `INVALID_REQUEST`, `LIMIT_EXCEEDED`,
  `IDEMPOTENCY_CONFLICT`, `OPERATION_PENDING`, `BUNDLE_BUSY`, `STORAGE_UNSAFE`,
  `STORAGE_CORRUPT`, `MIGRATION_REQUIRED`.
- SQLite constraint failures are never blindly exposed. Expected uniqueness races are reselected;
  impossible CHECK/FK/canonical disagreement is sanitized `STORAGE_CORRUPT` and poisons the
  runtime entry.
- `SQLITE_FULL`/IO/fsync failure before COMMIT yields no acknowledged state. COMMIT response loss
  is ambiguous and resolved only by identical retry.
- Object IO/parser/ID generation while a transaction is open is forbidden and asserted in tests.
- Empty valid source produces zero batch rows, a `plan_ready` job, report-ready evidence, and an
  honest terminal report with `empty_public_stream` gap.
- Raw source/stderr SHA audit digests exist only inside encrypted metadata/report objects; SQL,
  WAL, SHM, logs, errors, and reprs contain neither digest nor plaintext.

## Invariants

1. One source identity row owns one immutable publishing writer, batch/event plan, report object,
   and terminal result forever.
2. Every state/phase/lease transition is one generation-fenced transaction on the task's sole
   writer thread.
3. No SQLite transaction spans object/parser/ledger/clock/ID IO.
4. Every candidate batch and report event is published through normal `publish_work`; importer SQL
   never inserts an event/projection row.
5. `report_ready` pins object plus exact evidence draft before any final evidence append.
6. Check/receipt pending-import exclusion is repeated atomically in their ledger transactions.
7. Import object refs in structural tables are verified inventory roots; unselected captures are
   ordinary GC-safe orphans.
