## Purpose

This future resource is the exact wheel-installed copy of the reviewable bundle migration. It
makes strict-local bundle creation and migration independent of a source checkout while keeping one
auditable SQL authority.

## Public surface

Logical resource name: `migrations/bundle/0001.sql`. The installed manifest binds its destination,
source, media type `application/sql`, byte size, SHA-256, migration family `bundle`, and version
`0001`. It has no Python exports and no supported direct user override.

## Behavior

The resource-generation step performs an opaque byte copy from `migrations/bundle/0001.sql`.
Neither the packaging backend nor platform may alter line endings, whitespace, comments, statement
order, projection DDL, pragma values, or final newline. Before any DDL, the installed loader:

1. resolves the resource using the distribution resource API;
2. enforces the manifest's byte cap and reads exact bytes;
3. validates SHA-256 and size;
4. validates UTF-8 without BOM, LF-only lines, and one final LF;
5. returns decoded SQL only if the resource manifest itself has already verified.

All table/index/constraint and security behavior in `specs/migrations/bundle/0001.sql.md` therefore
applies identically. The copy is generated content: review changes happen in the root migration,
then the synchronization command updates this file and the manifest in one reviewable change.

This includes the complete generation/route recovery metadata keys, exact `maintenance_pins`
columns (including required privacy-root generation/digest) and state check, and
`maintenance_pins_one_active_operation` partial index. The installed
adapter is forbidden to synthesize or weaken this DDL when an older/corrupt package resource lacks
it.

Runtime never searches `$CWD/migrations`, user configuration, environment variables, network, or a
package index for alternate SQL. A patched or incomplete installed distribution fails closed before
creating or upgrading a bundle.

## Errors and edge cases

- Missing, duplicate, unreadable, oversized, or digest-mismatched bytes produce a bounded resource
  integrity error and no migration transaction.
- Resources may be inside a zip-compatible loader; callers consume bytes/temporary traversal
  handles rather than retaining a presumed path.
- A manifest that names the same destination twice or uses a traversal/absolute/case-colliding path
  is invalid even if both digests match.
- Diagnostics never print SQL, local installation paths, payloads, or arbitrary exception strings.

## Invariants

1. The embedded copy is byte-identical to the canonical root SQL.
2. Integrity verification completes before SQLite sees any statement.
3. Projection-table DDL is included in the same immutable digest.
4. Runtime cannot substitute or download a migration.

## Tests

- `specs/tests/packaging.md`: source/embedded equality across sdist, wheel, and clean install;
  manifest mutation cases and allowlisted contents.
- `specs/tests/integration.md`: create a bundle using installed resources, inspect exact schema,
  replay projections, and reject a one-byte-corrupt resource.
- `specs/tests/subprocess.md`: failure before staged-bundle publication when resource validation
  fails or the process is killed.
- Maintenance tests create/release/recover pins through the installed migration and verify wrong
  frontier/privacy-root/generation/lease, duplicate active pin, retained-route metadata and privacy
  constraints.
