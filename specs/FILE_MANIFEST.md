# Yoetz v0.1 — exhaustive future-file ownership manifest

**Manifest schema:** `yoetz.spec-file-manifest/1`
**Status:** Draft candidate for founder review. The founder choices in `specs/OPEN_QUESTIONS.md`
were resolved on 2026-07-15; individual rows remain draft until the specification freeze review.

This is the complete one-to-one ledger between the natural-language specification tree and the
files planned for the public v0.1 repository. It is declarative: adding, removing, renaming, or
splitting a future file requires changing this reviewed table and its owning spec together.

The inventory contains 528 spec files: 514 exact future-file owners,
10 directory indexes, and 4 coordination files. The 514 future paths are unique. The ten
already-authored public ADRs are current decision authorities, not future-file candidates, so
they are intentionally outside the mirrored ownership universe. Ignored local architecture/
strategy inputs are neither inventoried nor authoritative.

## Classification rules

- `future_file` owns exactly one future public-repository file and contains the complete seven-part
  natural-language implementation contract.
- `index_only` enumerates a directory family but owns no future file; every child still has its own
  `future_file` row.
- `coordination` governs the spec process or shared vocabulary and owns no future implementation
  artifact.
- Mapping semantics are frozen by `specs/scripts/verify_spec_manifest.py.md`. A row never relies on
  filename inference alone.
- `draft` means the file contract exists but has not yet passed founder freeze, empirical release
  evidence, and implementation review. Status changes are explicit row changes.
