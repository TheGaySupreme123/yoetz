# Yoetz v0.2.4 — consistent desktop installation

This patch in the 0.2 public-alpha line brings Codex, Claude Code, Cursor IDE and Cursor Agent
CLI into the same guided installation and connection lifecycle. It targets macOS, Linux and
Windows through WSL 2. Native Windows and mobile platforms remain unsupported.

## Changes

- Discover executable-backed installations, offer a host selection, and retain the exact selected
  profile and project in the connection preview and continuation.
- Connect Claude's plugin installation and enablement in one reviewed operation. Configure the
  appropriate Cursor project binding while preserving unrelated configuration.
- Show installed, enabled/configured, reload-required and connection-observed state separately.
  Repeated setup can be a no-op; interrupted work remains inspectable and retryable.
- Disconnect both plugin activation and managed MCP registration, retain Yoetz data, and support
  reconnect through the same flow.
- Keep Linux/WSL PAM approval on the foreground thread. When terminal handover is unavailable,
  show the exact approved continuation instead of failing the TUI worker.
- Keep the selected runtime first in the host handoff's PATH, alongside explicit profile and
  isolated-instance bindings.

The version-report schema advances to 2.2.2 for the added host-connection contract. Released
2.2.1 and earlier schema bytes remain unchanged. The public protocol namespace remains 0.1.

## Verification and limits

[Issue #767](https://github.com/TheGaySupreme123/yoetz/issues/767) and
[PR #788](https://github.com/TheGaySupreme123/yoetz/pull/788) record source, installation evidence,
review disposition and release status. Installation verification covers preview, apply, status,
repeat setup, disconnect and reconnect. Model-provider authentication and full model tasks are
outside this patch's requested acceptance scope. Configuration success does not assert a working
model session, complete observation, or AI-powered review.

The installed candidate uses the same wheel on macOS arm64 and Linux x86-64. The installation
matrix records configuration and lifecycle checks, not GUI/session activation:

| Host | macOS arm64 | Ubuntu 24.04 x86-64 | Ubuntu 24.04 on WSL 2 |
| --- | --- | --- | --- |
| Codex CLI 0.153.4 | Passed | Passed | Passed |
| Claude Code 2.1.261 | Passed | Passed | Passed |
| Cursor Agent CLI | Passed (2026.08.25) | Passed (2026.09.18) | Passed (2026.09.18) |
| Cursor IDE | Passed (3.20.0) | Passed (3.21.16) | Windows-side Remote WSL cell unverified |

Each passed cell includes preview, install/connect, status, repeated no-op setup, disconnect and
reconnect using an isolated installed runtime. A real interactive Linux installation also passed
its confirmation and single password prompt. macOS uses the owner's real OS approval; Linux and
WSL use disposable local accounts and the real PAM console path. The Windows-side Cursor IDE
cell remains owned by the integration maintainer in #722; CLI evidence does not establish it.

Required OS identity checks, repository trust, observation consent, provider credentials and
disclosure permissions remain separate. Headless Linux/WSL without secure storage still uses
the supported passphrase route; this patch does not resolve every onboarding limit in #737.
The observation and platform limits recorded in v0.2.3 remain in effect.
