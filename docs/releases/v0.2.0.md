# Yoetz v0.2.0 — three hosts, bounded observation, and guided upgrades


Yoetz v0.2.0 is the next official public-alpha release of the local evidence ledger for agent
work. It adds first-party Claude Code and Cursor integrations alongside Codex, captures consented
host activity with explicit coverage limits, and improves recovery when sessions, services, or
review attempts are interrupted. New observation controls keep routine reads bounded while
preserving failures and important evidence. Guided upgrades separate package replacement, data
migration, and host refresh so an installed package is not mistaken for an active integration.

Released from `main`. Python and npm packages both use version **0.2.0**. The public protocol
namespace remains **0.1**; package versions and versioned wire contracts advance independently.

## Highlights

- **Focused and Detailed observation selection.** Focused mode groups only proven successful
  routine reads into bounded structural summaries. Detailed retains eligible calls individually;
  failures, edits, tests, unknown outcomes, and explicitly protected evidence remain individual in
  either mode. Session overrides and workspace defaults have preview, apply, status, expiry, and
  revoke paths. Standard, larger, and largest capacities stay bounded; greater capacity is not a
  sustained-throughputput promise. Read protection and buffered promotion preserve important
  evidence without widening capture or disclosure authority (ADR-029, #687/#688).
- **Recovery under observation pressure.** Capture reservations and durable accounting keep
  structural pressure and captured-content limits separate. Unknown capture inventory can run a
  bounded recovery scan before rejecting new admission, while prior losses remain visible. Hook
  deadlines and partial capture produce explicit gaps instead of success claims (#692/#693,
  #695; integrated in #685).
- **A complete upgrade guide.** `yoetz upgrade` shows package, data, host-refresh, and verification
  stages for your existing hosts. Its explicit package action supports ordinary uv-tool installs
  and refuses source checkouts and pinned test runtimes. Release notices refresh from the consented
  cached update channel; declining one advertised version does not decline every later release.
  Package replacement does not silently migrate data, refresh host files, or broaden privacy
  choices (#699/#700).
- **Direct guidance for each host.** Codex, Claude Code, and Cursor receive their own skills and
  recovery instructions. Fresh sessions are instructed to read guidance, discover schemas, and
  call `start` before substantive work. A failed start follows its exact continuation; this is
  instruction delivery, not an enforcement gate. Closure guidance distinguishes publication,
  checks, findings, and a final receipt (#694/#701, #672/#677/#685).
- **Independent installations and test instances.** A runtime can be sealed to its own isolated
  root, lifecycle, source revision, and wheel identity. A dropped environment variable cannot send
  that pinned launcher to the everyday service. Instance status and disposal target the selected
  instance, with no deletion of the everyday installation (ADR-028, #604/#606).

- **Claude Code and Cursor are first-party hosts.** Each host has its own adapter, native plugin
  projection, privacy-minimized hook ingress, MCP ownership classification, and a runbook that
  records what is and is not supported. The exact implementation cells are Cursor IDE `3.17.8`
  and Cursor Agent CLI `2026.07.09-a3815c0` (#153/#401, #409–#411/#414, #423, #426/#451,
  #468/#474), and Claude Code CLI `2.1.241` as a local-process, project-scope, private-marketplace
  native plugin (#154/#424). Both hosts share the portable Agent Plugins carrier and activation
  contract of ADR-023 (#149/#384, #150/#385, #151/#386, #152/#391, #395/#481). Per-host plugin
  lifecycle commands refuse what a host cannot run instead of advertising it (#465/#472), Codex
  gains consent-gated plugin and MCP uninstall (#419/#421), and Cursor plugin apply is bound to a
  macOS LocalAuthentication presence check (#414). Proof facets stay separate: a rendered or
  installed artifact is never a model-use, observation, or receipt claim (see below).
- **Hooks attach themselves and say why when they cannot.** Consented `SessionStart` hooks on all
  three hosts now send the paired workspace/session selector `start` requires, so the natural
  auto-attach that v0.1 silently failed at actually happens (#459/#471). Ended-session recovery
  reattaches to the successor task and delivers the predecessor's still-pending rows (#535/#545,
  #577/#590), the resume/compaction probe is repository-bound so a live mapping is no longer
  reported stale, `SessionStart` context names the mapped session and attach selector, and Claude
  Code's bare-string `start` result binds the mapping (#578/#580/#581/#589). Every failure records
  a closed `hook_diagnostics` token — workspace binding, consent, storage, auto-attach, and start
  binding — and Claude Code advice uses the documented `additionalContext` channel rather than an
  error (#338/#412/#415–#417/#420/#428/#435/#441, #466). Migration `0009` stores Claude Code and
  Cursor hook rows in the task ledger; existing bundles migrate explicitly (#576/#586).
- **Observation drain and replay are reliable across restarts, rewinds, and reattach.** Frontier
  motion recovers across ledger rewinds and service restarts (#331/#482, #332), a check parked on
  a repository-grant handoff no longer blocks every observation append (#445/#453), one
  undecodable pending operation is quarantined instead of latching the whole ledger as corrupt
  (#427/#446, #443/#454), replay and drain keep their liveness invariants and quarantine
  non-retryable rows once as `ledger_rejected` (#539/#540/#544), committed operations replay across
  workflow reattach when the session and writer rotate (#560/#573), and Yoetz's own MCP workflow no
  longer starves hook drains (#564/#574). Consented hook capture now materializes secret-scanned
  tool output, changed-file bytes, diffs, and bounded snapshots as immutable ledger evidence with
  `observation_captured` provenance (#302/#488), scanned before encryption (#397/#450).
- **Privacy consent through conversation: Assisted and Expanded lanes.** A capable agent can guide
  semantic-review setup in ordinary chat, recommend Expanded first, explain Assisted, Metadata-only,
  and Private, show one complete frozen before/after repository privacy preview, and relay the
  user's one exact approval; consent schemas move to 6.0.0 so the pending target binds recipe,
  policy diff, repository, authority, review profile, and provider/model/endpoint, and drift on
  any of them fails closed (#164, #532/#533/#542, #519/#523, #510/#514). Codex may authorize
  through current-chat attestation; Claude Code and Cursor carry the selected outcome into the
  shortest trusted-local continuation instead of downgrading it.
- **Docs correction (#553, part of #570):** the README, the architecture overview, and
  `CONTRIBUTING.md` no longer claim that only a reauthenticated local human can loosen effective
  policy. Since #164 and #542, the user's explicit current-chat instruction, relayed by a capable
  agent through the consent lane for one exact prepared, previewed, expiring target, is a second
  reauthenticated loosening path. That relay is an agent attestation Yoetz cannot independently
  authenticate, so the trusted local ceremony remains the stronger path. Sensitive-confidential
  content and the never-send set stay absolute at every sink under either path (ADR-009), and
  presence-only operations keep their trusted-local authority boundary (ADR-016).
- **Codex-subscription semantic evaluator.** The exact Codex npm `0.150.1` macOS-arm64
  app-server cell can perform privacy-gated semantic review with a ChatGPT subscription; Codex
  stays the sole OAuth authority and no token enters Yoetz (#404/#480, #525/#526, #530/#531, #527,
  #534/#541, #520/#524). The exact selected model is shown before login and bound only after
  Codex's `model/list` reports it for the signed-in account; new bindings default to
  `gpt-5.6-luna`, omitted model selection preserves an existing binding (including during account
  switching), and an explicit `--model` always wins (#513/#592). The default model is independent
  of the evaluator's `high` reasoning setting; historical `gpt-5.6-sol` acceptance evidence remains
  Sol evidence and is not relabeled as Luna.
- **A paired fallback semantic endpoint (#582/#588).** The Codex subscription and an API provider
  can be paired in either primary/fallback order with `--as-fallback`, `yoetz provider fallback
  primary`, and `yoetz provider fallback remove`. Each destination requires its own
  privacy-approved binding, fresh attempt authorization, and receipt; the fallback engages only
  for a closed could-not-serve set (two licensed failures, quota exhaustion, or exhausted primary
  attempt slots), never for content-shaped failures, policy or human outcomes, or uncertain
  dispatch. Provenance and every receipt rendering name the serving fallback and the primary's
  failure reason as `fallback_from`. Privacy policy schema 1.1.0 adds the binding; released 1.0.0
  bytes are unchanged.
- **Semantic review that recovers instead of giving up.** One repair retry for an incomplete
  provider response inside the existing budget (#348/#461), awaiting-human checks recover across
  restart (#141/#485), host tool-call admission for the owner-authorized semantic check with an
  explicit way out (#467/#478), Codex MCP registration drift is named instead of a bare ceiling
  (#537/#543), and append-only completion-claim correction lets an agent replace a claim rather
  than pile a contradicting one on top (#432/#486, ADR-025).
- **Vault, keyring, and staged initialization.** Installation-vault recovery and trusted unlock
  flows (ADR-024, #407), reliable passphrase setup and rotation (#489–#491/#492), a generated
  initialization credential staged until proven (#511/#515) with the bundle root prepared before
  the guard opens (#565/#572), the vault result validated before an approval is consumed
  (#510/#514), and a typed initialization continuation for the start-first dead end (#512/#516).
- **Receipts and findings that match the evidence.** A finding resolves only by a later
  qualifying check, and hook-observed findings resolve after host-limited repair or host
  observation gaps without pretending the gap is closed (#458/#462, #538/#546, #547/#559); MCP
  markdown and text receipts keep their sections (#437/#447); a completion claim that cites a
  failed result is limitation disclosure, not support (#429/#447); a paginated `results` status
  view resolves result ids without result prose (#342/#433/#440/#448); failed multi-object appends
  abandon their stranded objects (#339/#483/#536); approved-check process groups are reaped on
  timeout (#399/#402).
- **MCP bridge and isolation.** Typed local-control failures instead of opaque `INTERNAL_ERROR`
  (#460/#470), a bounded nesting depth that keeps the bridge alive on deep JSON (#394/#473), one
  shared availability latch for concurrent first arrivals (#469/#474, #476/#477), `EVENT_INVALID`
  names its `reason_code` on the text channel (#579/#587), actionable evidence co-requirement hints
  (#335/#406), and a supported `YOETZ_ISOLATED_ROOT` contract (ADR-026) that derives runtime
  identity from one owner-only root within the exported process tree, including across Codex's
  external MCP registration. ADR-028 runtime pinning additionally protects bare launchers (#518/#522, #561/#575,
  #517/#521).
- **Codex integration honesty.** Rollout JSONL for Codex `0.148.0` and `0.150.1` has exact
  fixture-proven parser profiles; newer releases use only the explicitly reviewed compatibility rules and remain
  separate from native host-support proof (#418/#425/#422, #568/#583). Plugin activation reports
  `installed_not_activated` for a modified tree instead of `not_installed` (#347/#396/#449),
  activation recommendations bind the exact target (#463/#464/#475), and bounded Codex JSONL
  publication is authorized through the review lane (#301/#487).
- **Release and packaging.** The v0.1.0 publication was recovered through an immutable-tag recovery
  mode, partial-registry reconciliation, and offline tagged tests, and the scanned CycloneDX SBOM
  is attached (#366: #373–#380, #403/#408). GitHub releases are now derived from
  `docs/releases/<tag>.md` (#393); `AGENTS.md` and its `CLAUDE.md` alias carry the operator
  guidance for coding agents (#455/#456/#457).

## What this release does not claim

- It has not received the two independent security reviews required before the first non-alpha
  release; they remain deferred with binding conditions (`docs/OPEN_QUESTIONS.md`, ADR-004,
  ADR-008).
- It publishes no verified Codex-version, hook-observation, provider-endpoint, keyring/platform,
  or structural subject-capture support cell where release-bound evidence is absent. The exact
  `0.148.0` and `0.150.1` rollout parser profiles are parser proof, not host support, and say
  nothing about skills, MCP, hooks, or activation. `yoetz state capture` stays fail-closed with
  no advertised cell.
- The Cursor and Claude Code cells are implementation rows, not `supported` rows. For Claude Code
  `2.1.241`, strict validation, installation, discovery, registration, and connected plugin MCP are
  proven; model use, accepted observation, semantic dispatch, privacy receipt, and workflow receipt
  remain unobserved. Cursor SDK rows are deferred metadata. Claude Desktop, remote/web, managed
  and user scopes, Agent SDK, headless sessions, and Cursor Cloud are unpopulated cells. Neighboring
  host versions inherit nothing.
- A configured or logged-in Codex-subscription evaluator is not by itself a release capability
  claim, and a default or recommended model is a preselection, not entitlement proof. Only the
  exact packaged two-check and negative-control evidence in the evaluator runbook can promote a
  cell; recorded acceptance evidence against `gpt-5.6-sol` stays exact-head evidence for that model
  only, and neighboring Codex versions, platforms, plans, and models do not inherit it.
- Fallback pairing is a configuration and authorization contract. No live paired-dispatch
  interoperability is claimed, and recommendation eligibility still reads the primary's exact route.
- An agent-attested current-chat approval is not independent proof of the user's words: Yoetz
  binds the exact pending target and digests but cannot authenticate the relay. Hosts that cannot
  attest the decision require the trusted-local continuation.
- Host tool-call admission is host authorization, not dispatch proof; it does not widen policy and
  host configuration is not compare-and-swap.
- Portable backup restore is called portable only after a clean-profile drill, which is not
  evidenced; `recovery.machine_bound_vs_portable` stays `not_yet_evidenced`.
- It makes no support-mailbox delivery-time, response-time, or availability promise.
- On Linux, approved external-command checks fail closed because the bubblewrap launch profile is
  not release-certified. Built-in deterministic checks and the ledger remain available; Yoetz does
  not claim that an external command ran when its sandbox boundary is unavailable.
- It does not claim bit-for-bit reproducible Python archives, package signing, or broad platform
  support beyond the exact release jobs and artifacts that passed. Native launchd/systemd
  installers and a public `yoetz doctor` command remain deferred.
- Product-telemetry, crash-diagnostics, and capability-testing transports remain unavailable;
  `update_checks` is the only owned non-LLM transport and never carries task or user content.
- Semantic output is advisory. Yoetz records challenges and provenance; it does not replace code,
  security, or maintainer review.

These are bounded release statements, not fine print. The exact claim inventory and dated
dispositions are in
[`docs/public-claims.json`](https://github.com/TheGaySupreme123/yoetz/blob/v0.2.0/docs/public-claims.json)
and
[`docs/OPEN_QUESTIONS.md`](https://github.com/TheGaySupreme123/yoetz/blob/v0.2.0/docs/OPEN_QUESTIONS.md).

## Install

The canonical package is the Python distribution:

```text
uv tool install --managed-python --python 3.14.6 "yoetz==0.2.0"
yoetz
```

For a one-off run:

```text
uvx "yoetz==0.2.0"
```

Or, when `uv` is already installed:

```text
npx yoetz@0.2.0
```

The npm package is a dependency-free launcher. It bundles no Python and no Yoetz implementation;
it delegates unchanged arguments and terminal I/O to `uvx yoetz==0.2.0`.

### Upgrade from v0.1.0

Stop existing hosts/hooks and the old service through their supported lifecycle before replacing
the package. For an ordinary uv-tool installation, install this exact release with:

```text
uv tool install --upgrade --managed-python --python 3.14.6 "yoetz==0.2.0"
yoetz upgrade
```

Follow the guide for the hosts you already use. Refresh the selected host artifacts and launch a
fresh host process; Cursor may require a full quit and relaunch. Existing bundles require the
backup-first explicit migration procedure when reported; upgrading the binary or restarting the
service alone does not migrate task data. The release includes bundle migrations through `0012`,
including `0009` for Claude Code/Cursor hook rows. Preserve your current provider and privacy
choices unless you separately approve changing them.

See the [upgrade guide](https://github.com/TheGaySupreme123/yoetz/blob/v0.2.0/docs/usage/upgrading.md)
and [observation controls](https://github.com/TheGaySupreme123/yoetz/blob/v0.2.0/docs/usage/observation-selection.md).

## Release integrity

The tag workflow builds each distribution once, tests the candidate artifacts, records SHA-256
checksums and build provenance, assembles the release evidence and capability matrices, then
crosses dedicated publication environments. PyPI publishes first. npm then publishes the exact
approved launcher tarball through trusted publishing. The GitHub release attaches both candidates
and the evidence bundle. Post-publication jobs download the public artifacts and compare them to
the approved bytes. The immutable schema tree is deployed from the exact candidate before tagging
and the workflow re-fetches every hosted file for byte comparison.

Inspect the attached `SHA256SUMS`, `NPM_SHA256SUMS`, candidate manifests, `REPRODUCIBILITY.txt`,
CycloneDX SBOM, support matrix, known limitations, release-evidence bundle, and `VERIFY.md`
alongside the wheel, source archive, and npm tarball.

## Security and support

Report vulnerabilities through GitHub private vulnerability reporting, with
`support@yoetz.dev` as the fallback. Use repository issues for ordinary bugs and support. See
[`SECURITY.md`](https://github.com/TheGaySupreme123/yoetz/blob/v0.2.0/SECURITY.md) and
[`CODE_OF_CONDUCT.md`](https://github.com/TheGaySupreme123/yoetz/blob/v0.2.0/CODE_OF_CONDUCT.md).
