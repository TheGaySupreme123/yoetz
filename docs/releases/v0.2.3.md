# Yoetz v0.2.3 — integration and session recovery fixes

This patch in the **0.2 public-alpha line** repairs existing installation, transport, observation
and receipt behavior. The separate 0.3 feature line is unchanged.
[Issue #786](https://github.com/TheGaySupreme123/yoetz/issues/786) records the tested artifacts,
maintainer release decision and remaining verification limits.

## Repairs

- Privacy receipt list/get serialize stored timestamps and accept the existing local disclosure
  purpose without changing stored receipt bytes or the external-egress purpose grammar.
- Codex setup uses the selected Codex home for both plugin activation and MCP registration. When
  activation changes the effective MCP entry, the interactive wizard displays the refreshed
  preview for confirmation. Foreign entries and subsequent drift still refuse.
- Newer Codex transcript records retain their surrounding message when optional metadata contains
  fractional numbers. Compatibility parsing does not promote exact-version capability support.
- Cursor project registration writes the validated absolute project path. Cursor Agent CLI
  passes the IDE placeholder literally; the absolute path allows startup. Native roots and owned
  registration must still agree. Existing placeholder entries remain valid for IDEs and can be
  upgraded through an accepted preview.
- Transport send failures retain their retryability. Existing selected observations, protected
  reads and bounded routine summaries can cross local control without schema rejection.
- Routine-read classification retains its proven outcome. Older buffered groups that cannot
  qualify as summaries drain as their original individual records, preserving source order and
  their actual outcome limitations instead of blocking later hooks.
- Session attachment waits briefly for existing runtime users and yields a stopped busy-start
  lease without losing its durable identity. Exact-request retry guidance now reaches CLI and
  MCP. Optional background reviews yield to attachment, retain cancellation accounting, and
  release their runtime once even when multiple hosts reconnect. Observation ingestion also
  releases its runtime when optional final backlog feedback fails or is cancelled.

Request and result control schemas advance independently to 2.6.1. Released 2.6.0 schemas remain
byte-identical. The public protocol namespace remains 0.1; package versions are independent.

## Verification and limits

The release is available as the Python `yoetz` package on PyPI, the version-matched `yoetz` launcher
on npm, and the GitHub release assets. The npm launcher requires `uv` and installs the same exact
Python version. Use `uv tool install --python 3.14 yoetz==0.2.3` or `npx yoetz@0.2.3`.

Verification used independent installed test instances and synthetic workspaces. The final runtime
candidate passed full CI; independently built Mac and WSL wheels had identical bytes. The tagged
release workflow separately verifies its built artifacts before publication and downloads the
published distributions afterward.

Known limitations retained in this release:

- Observation is bounded and may be incomplete. The final Mac Codex default-capacity run reported
  eight unrecoverable observations and an overflow diagnostic; a larger-capacity follow-up reported
  seven additional losses. Both queues drained. Different native calls and a reused task prevent a
  controlled causal comparison; increasing capacity is not a promise of lossless capture.
- One follow-up MCP dry run timed out and its recovery read returned `frame_invalid`. The exact
  replay recovered; a fresh connection could inspect the operation. #786 retains this sequence
  for follow-up rather than treating it as a clean transport run.
- Strict/private test routes deliberately blocked AI-powered review. Their receipts remain
  coverage-limited. Optional hook advice can describe this policy ceiling as a provider-readiness
  problem; the typed check result is authoritative.
- Cursor Agent CLI 2026.09.18-9a7762b needs explicit registered-project binding because it does not
  provide matching MCP roots/list. Desktop retains mandatory roots binding. Linux CLI results do
  not establish Linux desktop behavior.
- Headless Linux/WSL without an approved credential backend uses explicit passphrase setup and
  unlock. Keep state on the Linux filesystem, never a Windows-mounted drive. Easier onboarding
  remains tracked in [#737](https://github.com/TheGaySupreme123/yoetz/issues/737).
- First-run setup connects Codex only. Claude Code and Cursor installation remain separate;
  multi-host first-run setup is tracked in #767 and is outside this patch.

The maintainer approved publication with these limits after reviewing the recorded tests. This
release does not claim complete observation, AI-powered verification, or universal host/platform
readiness. Native coverage follow-ups remain open in #786.
