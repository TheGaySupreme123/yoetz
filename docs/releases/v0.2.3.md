# Yoetz v0.2.3 stabilization candidate

This is an **unreleased candidate** in the 0.2 public-alpha line. It repairs existing installation,
transport, observation and receipt behavior. It does not include the new functionality on the
separate 0.3 branch. Issue [#786](https://github.com/TheGaySupreme123/yoetz/issues/786) owns the
verification and publication gate.

## Repairs

- Privacy receipt list/get serialize stored timestamps and accept the existing local disclosure
  purpose without changing stored receipt bytes or the external-egress purpose grammar.
- Codex setup uses the selected Codex home for both plugin activation and MCP registration. When
  activation changes the effective MCP entry, the interactive wizard displays the refreshed
  preview for confirmation. Foreign entries and subsequent drift still refuse.
- Newer Codex transcript records retain their surrounding message when optional metadata contains
  fractional numbers. Compatibility parsing does not promote exact-version capability support.
- Cursor project registration writes the validated absolute project path. Cursor Agent CLI
  passes the IDE placeholder literally; the absolute path allows startup. Native roots and owned
  registration must still agree. Existing placeholder entries remain valid for IDEs and can be
  upgraded through an accepted preview.
- Transport send failures retain their retryability. Existing selected observations, protected
  reads and bounded routine summaries can cross local control without schema rejection.
- Routine-read classification retains its proven outcome. Older buffered groups that cannot
  qualify as summaries drain as their original individual records, preserving source order and
  their actual outcome limitations instead of blocking later hooks.

Request and result control schemas advance independently to 2.6.1. Released 2.6.0 schemas remain
byte-identical. The public protocol namespace remains 0.1; package versions are independent.

## Verification limits

Verification uses installed wheels in independent test instances and synthetic workspaces.
Native model-issued MCP use, observation coverage, local checks and AI-powered review are separate
claims. Passing calculator tests or obtaining a receipt does not establish complete coverage.

- macOS and Linux native-host results and exact candidate identities are recorded in #786.
- Cursor Agent CLI 2026.09.18-9a7762b requires explicit registered-project binding because it
  does not supply matching MCP roots/list. Default desktop root binding remains unchanged; native
  CLI acceptance must be recorded separately in #786.
- Actual Windows/WSL 2 verification is deferred until a machine is available. Linux VM results
  do not verify WSL lifecycle, Windows-mounted filesystems, networking or desktop integration.
- Fresh headless Linux without an approved OS credential backend still requires the explicit
  passphrase setup/unlock path. The agent-mediated automatic vault initialization path is unavailable without that backend.
  The easier onboarding work remains [#737](https://github.com/TheGaySupreme123/yoetz/issues/737).
- Strict/local-only test routes cannot establish AI-powered review acceptance. Receipt coverage
  limitations and outstanding observation gaps remain release evidence, not waived criteria.
- Regular Cursor desktop MCP use is separate from candidate plugin hook activation; the maintainer's
  existing modified global plugin is preserved. Linux Cursor CLI evidence is not Linux IDE evidence.
- First-run setup still connects Codex only. Claude Code and Cursor installation remain separate;
  multi-host first-run setup is tracked in #767 and is outside this stabilization task.

Do not tag or advertise universal platform readiness from this candidate record. Publish only
after the owning issue records the accepted verification matrix and outstanding limitations.
