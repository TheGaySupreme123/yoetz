# Yoetz v0.3.0 — independent agent tasks and project coordination

Yoetz **0.3.0** is a public-alpha release that lets several agents work in independent tasks
inside one repository. Parents can delegate work, retain a child's unfinished obligations and
findings, and group related tasks into projects without granting access to arbitrary sibling
content. It also adds a backup-first data upgrade path from 0.2 and carries the install fixes
from 0.2.2. The capabilities below describe the implementation; native-host and release evidence
remain bounded by the limitations below.

Python and npm packages both use **0.3.0**. The public protocol namespace remains **0.1**;
package versions and immutable wire-schema versions advance independently.

## Highlights

- **Independent tasks, explicit delegation.** A parent can hand a child an expiring attach
  handle; child acceptance, cancellation, abandonment, closure and findings remain visible in
  lineage and receipts. A receipt does not close work or erase an unfinished dependency
  (#494–#504, #509, #706, #752).
- **Projects with bounded coordination.** Related tasks can declare overlaps under each source
  workspace's consent. Membership generations fence stale deliveries, grants can be revoked,
  and grouping can be disabled and re-enabled (#505–#508, #706).
- **Backup-first upgrades.** After unlock, the service upgrades supported older task ledgers
  before admitting writes, retaining verified backups and recorded progress for interrupted
  migrations. Package replacement and fresh host activation remain separate steps (#496).
- **Codex multi-agent v2 identity and recovery.** The bridge understands Codex 0.153.4 child
  rollout headers and token-usage records, preserves native replay identity, and keeps child
  lifecycle transitions distinct from session health. Native installed multi-agent acceptance
  remains open (#499, #507, #754, #752, #762).
- **Responsive reads and durable long reviews.** Immutable projection pages avoid repeated
  ledger replay for small status reads. Busy starts recover their durable route; long reviews
  preserve leases and authenticated responses through client disconnects and recovery rather
  than treating a client timeout as permission for a second dispatch (#745, #748, #750).
- **Install fixes carried forward.** The documented `uv` command fetches Python 3.14.6, the
  npm launcher installs persistently before delegating, and first-run Codex setup offers its
  default home. The npm release verifier now checks the launcher's two subprocess calls
  (#768, #774, #777).
- **Failures explain recovery and coverage.** Local CLI errors carry recovery directives;
  failed transport writes receive retryable transport classifications; oversized hook input
  reports a scoped coverage gap. Invalid routine summaries no longer stop admission flushes
  (#780, #781, #784, #764).
- **Advice and privacy receipts are more precise.** Paired edits produce one advice finding,
  verification baselines are typed, consumed egress is reconciled after cancellation, and
  privacy receipt commands render timestamps and admit the local purpose on the control wire
  (#782, #761, #783; fixes #731 and #732).
- **The release-runner test observes its drain.** The parent/worker capture test waits for the
  outbox to empty before the next write, instead of assuming a bounded hook pass drained it
  under runner load (#775).

## What this release does not claim

- **First run still connects Codex only.** Claude Code and Cursor use their documented native
  integration procedures. First-run detection and connection for both remains the open release
  gate in #767; it must land or be explicitly deferred before this candidate is tagged.
- **Real WSL 2 and AppArmor sandbox acceptance remain untested** (#720). Linux sandbox
  readiness is a fact of the client host; a Linux VM or package check does not prove WSL
  lifecycle behavior or a sandbox on a different host (#765).
- **Native Linux Claude Code and Cursor acceptance is incomplete** (#722). Their source and
  fixture coverage does not establish a native-host capability cell.
- **Native Codex multi-agent acceptance remains open** (#499, #507). Source tests and the
  0.153.4 identity repair do not prove installed host activation, correlated child observation,
  AI-powered review, corrective influence, or terminal receipt coverage.
- **No supported capability cell is added by this release number.** Runtime support remains
  `development_unverified`; macOS arm64 and Linux x86_64 evidence covers only the exact artifact
  and jobs that ran. Linux aarch64 remains untested; native Windows is not supported.
- **Migration tests are not prior-release restore certification.** No golden prior-release
  upgrade/restore cell or portable recovery drill is claimed. Package installation alone does
  not prove service, data, plugin, or host-session activation.
- **PyPI 0.0.1 is a yanked name reservation.** It was yanked on 2026-09-19 because it installs
  no usable executable. Normal version selection skips it; an exact `yoetz==0.0.1` pin can
  still select it. Install the current release on Python 3.14 (#771).

These boundaries follow
[`docs/public-claims.json`](https://github.com/TheGaySupreme123/yoetz/blob/v0.3.0/docs/public-claims.json)
and
[`docs/OPEN_QUESTIONS.md`](https://github.com/TheGaySupreme123/yoetz/blob/v0.3.0/docs/OPEN_QUESTIONS.md).
Checks report issues at their recorded coverage; they do not prove the underlying work correct.

## Install

```text
uv tool install --managed-python --python 3.14.6 "yoetz==0.3.0"
```

For a one-off run: `uvx --python 3.14 "yoetz==0.3.0"`. With `uv` already installed:
`npx yoetz@0.3.0` (the dependency-free npm launcher makes a persistent `uv tool install` of the
exact PyPI distribution).

Before upgrading an existing installation, stop its hosts, hooks and service writers and follow
the [upgrade guide](https://github.com/TheGaySupreme123/yoetz/blob/v0.3.0/docs/usage/upgrading.md).

## Release integrity

Verify the artifacts against the attached `SHA256SUMS`, `NPM_SHA256SUMS`, SBOM, support matrix,
known limitations, release-evidence bundle, and `VERIFY.md`. The tagged workflow binds the
candidate artifacts to their source commit, publishes PyPI before npm, and verifies registry
downloads. This makes no signing or reproducible-build claim.
